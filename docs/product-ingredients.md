# 전성분 및 피부 타입별 주의 성분 확인

2026-11-19 · ign8t `55cac379-260c-42a2-b6f4-3648f1c9883e`.

삭제 작업은 실제 AWS 연결 검증이 필요한 review 상태이고 현재 환경의 vault 설정은 여전히 유효하지 않다. 이를 임의로 완료 처리하거나 약관을 활성화하지 않았다. 프로젝트 → 마스터 스펙 → 다음 작업 순으로 재조회했고, 같은 마스터 및 ready/non-stale인 전성분 확인 작업 전문과 현재 규칙을 읽었다. 새로운 외부 계정 없이 사용자의 추천 근거 확인을 보완할 수 있어 이 작업을 선택했다.

## 기존 화면과 연결

카탈로그와 실제 리포트 경로 `/diagnostic/result/[reportId]`에서 기존 추천 컴포넌트와 상품 상세 native dialog를 재사용한다. 스펙 예시의 `/diagnostic/report/[reportId]`를 중복으로 만들지 않는다. 리포트의 화장품 링크는 해당 reportId를 보존하며 최신 리포트로 바꿔 읽지 않는다. 실제 추천을 비활성화한 환경에서는 리포트에 실제 추천처럼 가상 카드를 붙이지 않는다.

상품의 `전성분 & 맞춤 성분 분석` 버튼을 누르면 기존 상세창에서 분석을 조회한다. 콘텐츠는 내부에서 스크롤하고 닫기 버튼과 고정 면책 문구는 남긴다. 로딩 스켈레톤, 오류·재시도, 전성분 미등록, 원료 설명 미등록, 정상 성분·주의 표시를 구분한다. 검색은 목록을 지우거나 정렬하지 않고 일치한 표기를 강조한다. 원래 표시 순서와 중복 표기를 보존하며 `1,2-Hexanediol`의 쉼표를 구분자로 잘못 처리하지 않는다. ESC/닫기 후 원래 버튼으로 포커스를 돌려준다.

## API와 데이터

`GET /api/v1/catalog/products/[productId]/ingredients`

- productId는 UUID, 선택 쿼리는 유효한 16종 `baumannType` 또는 `reportId`뿐이다. 중복·추가·잘못된 값은 400이다.
- 상품 성분은 공개 정보지만 진단은 공개하지 않는다. 최신 진단은 DB로 검증한 회원 또는 HMAC으로 검증한 비회원의 COMPLETED 리포트만 읽는다. 명시한 reportId도 동일하게 소유권을 검사한다. 헤더의 사용자/게스트 UUID는 인증 증거가 아니다.
- 직접 선택한 타입은 선택 기준으로, 본인 진단은 진단 기준으로, 둘 다 없으면 공통 규칙 기준으로 표시한다. 선택 타입을 임의의 사용자 진단으로 표현하지 않는다.
- 응답은 표준 success/data 엔벨로프와 제품명, 브랜드, 타입/출처, 성분별 원료 특성, 진단 추천 일치 여부, 주의 성분/이유/수준, 전성분, 면책/검사 범위 안내를 포함한다. 원시 규칙 테이블·제휴 원본 URL·리포트 요약·소유자 ID는 보내지 않는다. 응답은 private/no-store다.
- 실제 카탈로그 모드에서는 활성 제품만 읽으며 없는/비활성 제품은 404다. 기존 `fullIngredients`만 전체 표기의 근거로 삼고, 미등록일 때 `keyIngredients`나 부분 태그를 완전한 전성분으로 대체하지 않는다.
- 체험 모드에서는 기존 가상 샘플만 사용하고 isDemo=true를 반환한다. 실제 소매 제품의 전성분 또는 피부 적합성이 검증되었다고 표현하지 않는다. 임의의 DB 상품을 체험 모드로 공개하지 않는다. 체험 UI는 기존 오프라인 동작을 유지해 상품 API를 호출하지 않고, 가상 상품에는 검증된 전성분이 없다는 안내를 보여 준다.

## 규칙과 추천 필터

신규 `IngredientCautionRule` 모델/마이그레이션만 추가했고 기존 products 구조는 변경하지 않았다. 초기 대표 규칙 7개를 새 마이그레이션으로 기록했다. 서버에서만 DB 규칙을 조회하고, 관리자 수정 API는 만들지 않았다. 향후 규칙 수정도 검토한 신규 마이그레이션 등 승인된 운영 절차로 남겨야 한다.

변성알코올/에탄올, 향료, 일부 세정 성분, 각질 정돈 성분 및 페퍼민트오일의 표기·INCI 별칭을 정확한 이름 단위로 비교한다. 알코올이라는 부분 문자열만으로 세테아릴알코올·세틸알코올을 휘발성 알코올로 분류하지 않는다. 세라마이드/히알루론산이라는 성분군 표기를 특정 세라마이드NP/소듐하이알루로네이트로 바꾸지 않는다. 농도·pH는 전성분 순서나 존재만으로 판단하지 않는다.

기존 추천 엔진에 같은 규칙을 전달하여 타입에 적용되는 CAUTION/WARNING 및 리포트의 별칭 일치 주의 성분이 있는 후보를 제외한다. 기존 상품 캐시의 최대 30초 갱신 주기는 유지하지만, 상세 성분 API는 현재 DB의 전성분을 새로 읽는다. 추천 카드를 받은 뒤 공식 표기가 변경된 경우에도 상세창은 최신 등록 주의를 표시할 수 있다.

## 스펙의 표현 조정과 한계

- 스펙의 `[안심]` 및 자극 성분 없음이라는 표현은 대표 규칙의 미검출만으로 입증할 수 없다. `등록된 대표 규칙에서 주의 성분이 검출되지 않았습니다. 자극이 없다는 뜻은 아닙니다.`로 표시한다. 제품을 유해/안전으로 이분하거나 모두에게 같은 반응을 단정하지 않는다.
- 표시 순서 유지와 가나다 정렬 요구가 충돌하므로 전성분 본문은 용기 표시 순서를 우선한다.
- 원료 설명은 보습·컨디셔닝 등 일반 원료 특성이다. 개인 알레르기, 제품의 완제품 임상 효과, 함량·배합, 모든 자극 성분, 규제상 기능성 인정 여부를 판정하는 엔진이 아니다. 초기 규칙은 전문가가 모든 피부 축의 위험도를 임상 검증한 체계라고 주장하지 않는다.
- `npm run ingredients:check`는 기본 규칙/설명의 치료적·절대적 문구를 검사하며 `npm run build`에서도 실행된다. DB 규칙과 표시 데이터는 런타임에도 같은 검사를 통과해야 한다. 실패를 무경고/안전 응답으로 바꾸지 않는다. 고정 면책 문구의 ‘치료 목적의 의약품이 아님’은 금지 효능 주장이 아니므로 별도 고정 텍스트로 둔다. 이 문자열 검사만으로 법률 적합성 전체를 보장한다고 주장하지 않는다.
- 실제 판매 제품 50~100개의 공식 전성분을 새로 수집·검증한 작업이 아니다. 기존 체험 카탈로그와 실제 데이터 연결 상태를 유지하고, 허구의 실제 브랜드/구매처/효능을 만들어 등록하지 않는다.

공개 배포·Git push·환경 게시·기존 환경 삭제·약관 활성화는 수행하지 않는다. `8b4c542` 원본은 미복구 상태를 유지한다.

## 검증 기록

- `npm run db:migrate`, `npm run db:generate`: 폐기 가능한 로컬 PostgreSQL에 신규 규칙 테이블/초기 7개 규칙 적용 및 타입 생성 성공.
- `npm run test`: 전체 단위 274개 통과. 기존 16종 타입 추천과 신규 표기/별칭·지방알코올 오탐 방지·건성/민감 축 분리·농도 추측 금지·원료군/특정 성분 구분·치료 표현 검사·추천 후보 제외를 검증했다.
- `npm run test:db`: 총 166개 중 기능 165개 통과, 기존 추천 p95 성능 검사 1개는 빌드 동시 부하에서 342.9ms로 300ms 기준을 초과했다. 동일 기준을 유지하고 빌드 종료 후 `npm run test:db -- tests/database/catalog.test.ts` 9개를 단독 재실행하여 통과했다. 새 API 7개 통합 검사는 성공/404/입력 오류, 회원·서명 게스트 소유권, ID 헤더 위조/임의 reportId 거절, 전성분 없음, 비활성 제품, 체험 모드의 DB 비공개, DB 장애·미검토 문구 거절을 검증했다.
- `npm run test:e2e` 전체 회귀 뒤 변경 화면을 집중 재검증했다. 검색 입력의 첫 Escape가 창 닫기를 막는 실제 문제와 체험 모드의 API 호출 회귀를 수정했고, 스크롤 영역의 키보드 접근도 보완했다. `npm run test:e2e -- tests/catalog.spec.ts tests/skin-shop.spec.ts` 10개 통과. 리포트 페이지 변경은 `tests/diagnostic-report.spec.ts` 4개 및 본인 리포트에서 실제 성분 상세창을 여는 신규 검사로 확인했다. 초기 전체 실행의 나머지 회귀와 합쳐 기존 95개 및 신규 6개 시나리오를 검증했다.
