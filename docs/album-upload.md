# 앨범 사진 업로드

`/diagnostic`에서 JPG·PNG·WebP 파일을 선택해 기존 보안 업로드 API로 전송합니다.
실시간 카메라, 얼굴 검출, 문진 렌더링과 AI 분석은 이 작업의 범위에 포함하지 않습니다.

## 동작

1. 확장자·MIME·원본 크기(10,240~10,485,760바이트)와 파일 시그니처를 확인합니다.
2. 브라우저의 `createImageBitmap(imageOrientation: from-image)`으로 EXIF 방향을 적용합니다.
   해당 API가 없는 브라우저에서는 네이티브 Image 디코더를 사용합니다.
3. 긴 축을 최대 1280px로 비율 유지 축소하고 Canvas에서 JPEG 품질 0.85로 다시 인코딩합니다.
   원본 메타데이터는 복사하지 않습니다. 최적화한 JPEG가 API의 최소 크기보다 작으면 Canvas PNG를 시도합니다.
   PNG도 크기 범위를 충족하지 못하면 다른 선명한 사진을 요청하며, 크기를 맞추기 위한 패딩이나 API 제한 우회는 하지 않습니다.
   원본 HEIC는 지원하지 않으며 JPG/PNG/WebP로 변환된 파일을 선택해야 합니다.
4. `/api/v1/diagnostics/upload-url`로 처리한 파일의 MIME·크기를 전송합니다.
5. 발급된 URL에 처리한 Blob만 직접 PUT합니다. `Content-Type`, `x-amz-server-side-encryption: AES256`을 전송하고
   브라우저가 Content-Length를 설정합니다. 외부 스토리지로 앱 쿠키를 전달하지 않습니다.
6. CORS로 노출된 ETag를 읽어 따옴표를 정규화하고 `/api/v1/diagnostics/upload-complete`에서 확정합니다.
   응답의 세션 ID·S3 키·UPLOADED 상태가 일치해야 성공으로 표시합니다.

## 상태와 인계

전처리·링크 발급·완료 검증은 불확정 진행 표시, PUT은 실제 업로드 바이트 기반 진행률을 사용합니다.
성공은 서버의 완료 확인 후에만 표시합니다. 전송 중에는 사진 선택·앱 헤더·하단 메뉴 이동을 막습니다.
브라우저 자체 탐색은 막지 않으며, 컴포넌트가 제거되면 진행 중 요청을 중단합니다.
디코딩한 bitmap은 전처리 직후 닫고, 미리보기 Object URL은 재선택하거나 컴포넌트가 제거될 때 해제합니다.
사진·URL·서명 URL을 localStorage나 로그에 저장하지 않습니다.

`OnUploadCompletePayload`는 확정된 uploadSessionId, s3Key, previewUrl을 전달합니다.
현재 부모 화면의 React 상태에 보관하며, previewUrl은 업로더가 마운트된 동안만 유효합니다.
문진은 아직 별도 미구현 기능이므로 다음 단계 버튼은 현재 화면의 문진 안내를 엽니다.
페이지 새로고침 후 클라이언트 인계 상태 복구는 지원하지 않습니다. 후속 문진 작업에서 이 계약을 소비해야 합니다.

발급·전송 실패에는 동일 처리 이미지를 이용한 재시도를 제공하고, 검증 실패에는 사진 재선택을 제공합니다.
재시도는 새 URL 발급부터 시작하므로 서버의 시간당 3회 제한에 포함될 수 있습니다.

## 검증 범위

단위 테스트는 크기 경계, 형식·시그니처, 리사이징, 인코딩 품질·자원 해제,
PUT 헤더·ETag·응답 검증·429·전송 실패와 UI 재시도를 확인합니다.
브라우저 테스트는 합성 JPEG에 실제 EXIF Orientation 6을 넣어 2000×1000 원본이
640×1280으로 처리되는지 확인하고 320px/1280px에서 API 순서와 성공·실패·다음 안내를 검증합니다.

스토리지 응답은 브라우저 인터셉터를 사용합니다. 실제 S3 자격 증명·CORS·업로드 속도는 이 테스트로 검증하지 않습니다.
실제 버킷에는 PUT 허용 및 ETag 노출 CORS 설정이 필요합니다.
S3 설정이 없는 환경에서는 실제 사진 전송이 실패 상태로 표시되며 성공으로 숨기지 않습니다.
