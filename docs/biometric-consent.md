# 안면 사진 동의 이력과 약관 버전 관리

ign8t 작업 `d9cf5551-ec72-4ae1-add0-c019e93d0be2`. 공개 배포·운영 DB 변경·실제 S3/유료 AI 호출 없이 로컬 구현과 검증을 진행했습니다.

## 현재 적용 범위

서버에 얼굴 사진을 등록하는 `/diagnostic` 흐름은 동의 확인을 거칩니다. 카메라 시작·촬영·전송과 앨범 이미지 처리 전에 현재 동의를 확인하고, 미동의나 구버전이면 동의 창을 엽니다. 체크박스는 처음과 약관 갱신 시 항상 선택되지 않은 상태입니다. 서버가 동의 기록을 저장한 뒤에만 진행하며, 취소하면 사진 전송을 진행하지 않습니다. 동의하지 않아도 문진은 이용할 수 있습니다.

기기 내 사진 체험 모드는 기존 계약대로 서버에 사진을 보내거나 분석하지 않으며, 이 동의 API를 호출하지 않습니다. 데일리 스냅샷의 별도 수집 정책과 회원 탈퇴 시 물리적 이미지 삭제는 이 작업에서 구현하지 않았습니다.

클라이언트를 우회해도 `createUpload`는 현재 활성 약관과 유효한 동의를 확인한 뒤에만 S3 서명과 업로드 세션을 만듭니다. 동의 없음·구버전·활성 약관 없음은 HTTP 403 `CONSENT_REQUIRED`입니다. 업로드 완료 검증과 기존 업로드 사진의 AI 처리 전에도 확인합니다. AI 처리 권한이 없으면 사진을 읽거나 공급자에게 보내지 않고 문진 기반 리포트로 명확히 전환합니다.

## 데이터와 불변 계약

기존 `user_consent_histories`와 회원 관계를 확장했으며 기존 데이터를 삭제하거나 의미를 바꾸지 않았습니다. `sensitiveAgreed`, `termsVersion`, `agreedAt` 등 기존 필드는 유지합니다. 회원당 한 건 제한을 제거해 회원·게스트의 여러 버전 동의를 새 행으로 저장합니다. 과거의 동의 플래그가 있어도 정식 약관 버전 FK에 연결되지 않은 레거시 기록은 현재 동의로 인정하지 않습니다.

새 `consent_terms_versions`에는 버전·전문·시행일·활성 상태를 저장합니다. DB의 부분 고유 인덱스로 동의 종류당 활성 버전을 하나로 제한합니다. 내용·제목·시행일·버전을 수정하지 못하는 트리거를 적용했으므로, 문안을 바꾸려면 새 버전을 만들어야 합니다. `isActive` 전환만 허용합니다. 미래 시행일은 아직 유효한 약관으로 사용하지 않습니다.

동의 사실의 주체(게스트 ID), 약관, 결정, 시각, IP·출처, 브라우저 정보는 UPDATE할 수 없습니다. 명시적인 예외는 검증된 OAuth 트랜잭션 안에서 `userId:null`인 게스트 이력에 회원 ID를 한 번 연결하는 것뿐입니다. 그 밖의 필드를 함께 바꾸거나 다른 회원에게 다시 연결하면 DB가 거절합니다. 기존 사용자 삭제 FK의 CASCADE는 보존하며, 이 작업에서는 사용자 대상 삭제 API나 일괄 삭제를 추가하지 않았습니다.

게스트 동의 기록과 로그인 이전은 같은 게스트 advisory lock을 사용합니다. 동의 제출과 업로드 발급은 활성 약관 행의 공유 잠금을 트랜잭션 안에서 유지하여 약관 전환과 경합하지 않도록 합니다. 신규 동의 요청은 검증된 소유자별 1시간 10회까지 허용하고, 기존 기록을 덮어쓰지 않습니다.

## API

| 경로 | 동작 |
| --- | --- |
| `GET /api/v1/consents/terms/latest` | 공개 활성 약관, 버전, 시행일. 활성 약관이 없으면 404 `TERMS_NOT_FOUND` |
| `GET /api/v1/consents/status` | 본인의 최신 동의와 재동의 필요 여부. 타인 선택용 쿼리는 거절 |
| `POST /api/v1/consents` | `{ consentType: BIOMETRIC_FACE_DATA, termsVersion, isAgreed: true }`. 성공 201, 잘못된 입력 400, 인증 없음 401, 바뀐 버전 409, 한도 초과 429 |

실제 회원 세션이나 서명된 HttpOnly 게스트 증명을 확인합니다. 임의 게스트 ID 헤더·본문의 userId/IP는 신원이나 감사 사실의 증거가 아닙니다. 상태·동의 응답에는 IP와 User-Agent가 포함되지 않으며 응답은 private/no-store입니다. 409를 받은 화면은 새 약관을 다시 조회하고 체크박스를 초기화한 뒤 사용자의 재확인을 받습니다.

## IP를 기록하는 조건

`CONSENT_TRUSTED_IP_HEADER`는 관리하는 앞단 프록시가 해당 헤더를 덮어쓰는 것을 확인했을 때만 설정합니다. 허용 값은 `x-forwarded-for`, `x-real-ip`, `x-vercel-forwarded-for`입니다. 첫 번째 값만 IP 문법 검증을 하며, 앞 값이 잘못됐다고 뒤의 다른 IP나 다른 헤더를 대신 선택하지 않습니다.

기본값은 비어 있습니다. 이때 IP는 `null`, 출처는 `UNAVAILABLE`로 기록합니다. Next.js Request에는 검증 가능한 소켓 원격 주소가 없으므로 임의로 127.0.0.1이나 헤더 값을 실제 이용자 IP로 만들어 넣지 않습니다. User-Agent는 길이 512자로 제한합니다. 프록시 신뢰 설정을 검증하지 않았다는 사실을 실제 IP 수집 성공으로 기록하지 않습니다.

## 실제 약관 활성화는 보류

마이그레이션은 `v1.0-draft`를 **비활성 검토 초안**으로만 넣습니다. 현재 보관·삭제 작업이 운영에 연결되지 않았으므로 ‘비회원 24시간 후 자동 삭제’나 ‘탈퇴 즉시 영구 파기’를 사용자에게 약속하지 않습니다. 활성 버전이 없으면 실제 서버 사진 저장은 막고 문진·기기 내 체험은 유지합니다. 초안의 전문은 동의를 받을 수 있는 완성 정책이 아닙니다.

운영 활성화 전에 실제 수집 항목(동의 감사의 IP/브라우저 정보 포함), 회원·비회원별 보관 기간, 삭제·철회 처리, 외부 AI 제공자/처리 범위와 보관 동작을 확인해 새 약관 버전을 확정해야 합니다. 원래 초안을 수정하는 방식으로 버전을 재사용하지 않습니다. 이번 작업은 약관을 게시하거나 환경 초안을 저장·게시하지 않습니다.

새 마이그레이션 `20261118000000_biometric_consent_versions`는 격리된 로컬 DB에만 적용했습니다. 운영에 코드를 반영할 때는 별도의 검토된 운영 마이그레이션이 필요합니다. 누락된 동의 스키마를 무시하거나 구버전 플래그로 우회해 사진 전송을 허용하지 않습니다.
