# 진단 앨범 사진 수동 보정

ign8t 작업: `3be141f7-74e8-46e4-9d31-6e7d1f49f7a8` — 스마트폰 조명·각도 보정 및 앨범 사진 수동 업로드 플로우.

마스터 스펙 및 ready 상태 작업 스펙을 읽은 뒤 구현했다. 기존 Next/React/Canvas 및 업로드 클라이언트를 재사용하며 패키지, DB 스키마, API 계약은 추가하지 않는다.

## 사용자 흐름

- `/diagnostic`에서 카메라와 앨범을 전환한다. 카메라 거부·미지원·영상 재생 또는 캡처 실패 시 안내 후 앨범 선택 버튼으로 포커스를 옮긴다. 저조도·얼굴·흐림 품질 경고는 기존 카메라 재촬영 안내를 유지한다.
- 동의 확인 후 JPEG/PNG/WebP, 10KB–10MB 원본을 보정 화면에 연다. 손상 파일은 전송하지 않는다.
- 타원 가이드 안에서 드래그/터치, 두 손가락 핀치, 확대 슬라이더(1–3배), 방향 버튼을 제공한다. 밝기·대비는 각각 -50~50이며 초기화로 위치와 조명 값을 모두 되돌린다.
- 확정 전에는 업로드 API를 호출하지 않는다. 확정 후 최종 이미지의 기존 품질 검사를 통과해야 업로드한다. 편집 중 동의가 철회되면 재확인에서 이미지를 폐기한다.
- 정확한 1280×1280 JPEG(quality 0.90)를 기존 `upload-url → PUT → upload-complete` 흐름으로 보낸다. AES256 헤더, ETag 및 응답 검증, 중복 전송 방지, 문진 세션 전달을 유지한다. 완료 콜백에 밝기·대비·배율 요약을 추가한다.
- 링크/전송 실패는 모달에서 보정 이미지를 재사용해 다시 시도한다. 확정 실패는 기존 정책대로 재선택을 요구한다. 한도/동의 오류 문구를 보존한다.

## 개인정보와 브라우저 호환성

- 원본은 EXIF-aware `createImageBitmap` 또는 브라우저의 네이티브 Image 디코더로 한 번만 회전시킨다. 수동 회전을 중복 적용하지 않는다. 회전된 픽셀의 편집 상태 `rotationDegree`는 0으로 정규화된다.
- 디코딩 결과를 최대 변 2048px의 편집 소스로 줄이고 원본 비트맵을 닫는다. 미리보기는 400px, 내보내기만 1280px 캔버스를 사용한다. 필터는 픽셀 연산으로 처리해 Canvas `filter` 미지원 브라우저도 지원한다.
- 영구 브라우저 저장소에 사진을 쓰지 않는다. 재선택/취소/언마운트 시 비트맵·소스 캔버스·미리보기 URL을 해제하고 진행 중 처리를 취소한다. 최소 용량을 맞추기 위한 패딩이나 PNG 우회는 하지 않는다.
- 사진 테스트 모드에서도 진단 앨범 보정은 가능하지만 서버 전송 없이 기기 내 미리보기로 끝난다. `/snapshot`에는 보정 기능을 활성화하지 않는다.
- 기존 하단 의료 면책 고지를 유지하고 진단 테스트 모드에도 진단 전 안내를 표시한다. 모든 보정 버튼/슬라이더는 44px 이상의 조작 영역과 키보드 입력을 제공한다.

## 검증 범위

단위 테스트는 크롭 경계·줌 기준점·필터 연산·2048px 소스 제한·1280px JPEG와 압축 설정·품질 검사·취소·동의 재확인·메모리 해제를 확인한다. 브라우저 검증은 320/1280px의 마우스·터치·키보드 조작, 초기화, 두 디코더의 EXIF 실제 픽셀 방향, 접근성, 확정 전 무전송, 보안 PUT 순서, 오류 재시도, 문진 연결, 테스트 모드의 무전송을 포함한다.

업로드 브라우저 테스트는 합성 이미지, 테스트 얼굴 검출기 및 가짜 스토리지 호스트의 요청 가로채기를 사용한다. 실제 AWS/S3·유료 AI·OAuth 및 운영 설정 활성화나 이번 변경의 공개 배포를 수행한 검증은 아니다. 실제 iOS 기기에서의 성능/호환성 검증은 별도로 필요하다.
