# 월별 피부 기록 캘린더

회원의 /snapshot 페이지에서 기존 촬영·저장 기능 아래에 월별 캘린더를 표시합니다. 마이페이지의 기존 데일리 기록 링크로도 들어갈 수 있습니다. 사진 테스트 모드는 기기 내 사진 미리보기 동작을 유지하며, 회원의 저장 이력은 별도 인가 API로만 조회합니다. 게스트에게 실제 기록을 불러오거나 가짜 썸네일을 표시하지 않습니다.

## 계약과 날짜

GET /api/v1/snapshots/monthly?year=2026&month=11. 연도1900~9998, 월1~12, 중복·미지원 파라미터 거절. 실회원 세션을 매번 DB검증하며 클라이언트가 조회 대상 userId를 지정할 수 없습니다. 성공200, 미인증401 UNAUTHORIZED, 잘못된쿼리400 INVALID_MONTHLY_QUERY, 한도429, 인프라실패503. 응답은 private,no-store 및 Vary:Cookie이며 다른 회원/게스트와 공유하지 않습니다.

기존 DailySnapshot 모델, snapshotView 프로젝션, signImageView(300초), KST 날짜 함수를 재사용합니다. DB의 recordDate는 타임존 없는 DATE이므로 순수 YYYY-MM-DD 키를 UTC자정 Date로 표현해 시작일이상·다음달시작일미만으로 검색합니다. 실제 createdAt 타임스탬프를 월 경계 판정에 사용하지 않습니다. 클라이언트의 지역 시간대와 무관하게 서버가 제공한 KST today 및 초기월을 사용합니다.

현재 연속일수는 조회월과 별개로 오늘부터(오늘없으면어제부터) 계산하며, 월·연도 경계를 넘어갑니다. 날짜만128개씩 역순조회해 첫 공백에서 종료하여 전체 개인정보/이미지를 불필요하게 읽지 않습니다.

응답 snapshots는 월내일자순이며 thumbnailUrl은 기존 비공개 GET서명입니다. 원본s3Key는 응답 필드에 포함하지 않습니다. 전체/썸네일 이미지 모두 서명URL을 사용하며 이미지최적화공유캐시를 통과하지 않고 referrerPolicy=no-referrer로 표시합니다. 일반안내 feedbackSource는 conditions=null로 유지해 DB기본등급을 AI측정으로 오인하지 않게 합니다.

## 화면과 갱신

7열 그리드는320px에서도44px이상 날짜터치영역을 유지합니다. 이전/다음달, 날짜선택, 일자목록, 하단사진·피드백·수분/진정/피지등급을 제공합니다. 문구/선택상태/썸네일로 의미를 전달하며 색만으로 상태를 나타내지 않습니다. 날짜선택 시 상세제목에 포커스합니다. 로딩·빈상태·요청실패·로그인만료·이미지실패를 구분합니다. 이미지가 만료되면 명시적 새로불러오기 버튼으로 서명URL을 다시 발급합니다. 이전월요청은 취소하고 응답을무시해 뒤늦은 응답이현재월을 덮지 않도록 합니다.

오늘기록 CTA는 기존 촬영영역 앵커로 이동합니다. 저장후 기존 router.refresh가 받은 오늘기록ID가 바뀌면 캘린더가 자동재조회됩니다. S3없는 사진테스트모드에서는 로컬사진을 저장하는것으로 안내하지 않습니다.

## 요청 제한과 운영 검증 범위

API는 인증된 사용자당 프로세스별 분당60회 제한과 만료정리/최대10000키로 메모리를 제한합니다. 클라이언트가 위조할 수 있는 IP헤더는 신뢰하지 않습니다. 신뢰할 프록시/공유rate-limit저장소가 없는 현재 환경에서는 다중인스턴스 공통IP제한을 제공하지 않으므로 운영엣지에서 별도 설정이 필요합니다. IP별 전역60회가 적용됐다고 주장하지 않습니다.

별도DB마이그레이션, 운영DB변경, 실제S3접속·스토리지구매·AI호출은 없습니다. 실제비공개버킷 접근검증은 기존 S3연결 작업과 함께 대기합니다. 자동검사는 실제 로컬DB와 AWS SDK서명으로 인가/월경계/스트릭/만료값을 확인하며, 브라우저화면은 개인정보없는 모의기록·이미지로 확인합니다.
