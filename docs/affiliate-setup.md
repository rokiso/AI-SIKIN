# 제휴 계정·실상품 연결 준비

2026-11-23, ign8t `1479673c-21d8-45da-a2c8-59c172584e9e`.

사용자가 아직 승인된 계정·발급 링크가 없으며 **연결 준비부터 진행**하도록 범위를 확정했다. 이 문서는 실제 제휴 승인·수익 추적·정산·실상품 검증이 완료됐다는 기록이 아니다. 기존 구매 중계 및 개인정보 보호 계약을 유지하고, 설정 점검과 안전한 로컬 등록 도구만 추가했다.

## 설정 점검

서버 전용 설정은 `.env.example`에 이름만 추가했다. 실제 값은 저장소 밖 개인 환경/시크릿에 보관한다.

- `AFFILIATE_PARTNER_ID`: 선택한 플랫폼에서 실제 발급받은 식별자. 예시 ID·공백/제어 문자만 있는 값은 통과시키지 않는다.
- `AFFILIATE_DEFAULT_PLATFORM`: 운영자가 승인된 플랫폼을 구분하는 대문자 식별명. 예: 실제 쿠팡 파트너스 계정을 승인받은 뒤 `COUPANG_PARTNERS`로 구분할 수 있다. 이 문자열 설정 자체는 가입 증명이 아니다.
- `CATALOG_AFFILIATE_HOSTS`: 기존 설정 재사용. 심사한 HTTPS 판매처의 정확한 호스트만 쉼표로 등록한다. 임의 기본 판매처나 와일드카드를 추가하지 않았다.

`npm run affiliate:check`는 DB·판매처에 접속하지 않고 로컬 설정 형식만 확인한다. 값 대신 잘못되거나 누락된 환경 변수 이름만 출력하며, 누락 시 종료 코드 1이다. 형식이 맞아도 가입 승인·정산·제공자별 트래킹 계약·실제 상품 링크는 `NOT_VERIFIED`로 남긴다. 현재 실제 환경에서는 위 3개 항목이 모두 미등록으로 확인됐다.

`AFFILIATE_SUB_ID_PREFIX`나 제공자별 `lptag`/`subid`를 임의로 추가하지 않았다. 플랫폼이 정해지지 않은 상태에서 모든 판매처에 같은 쿼리를 넣거나 새 ID를 만들어 제휴가 연결됐다고 표시하지 않는다. 실제 발급된 링크를 입력받아 기존 빌더에서 처리할 준비만 한다. 기존 빌더가 붙이는 UTM/click_id가 실제 제공자 링크·서명·허용 서브태그 정책과 호환되는지는 링크를 받은 뒤 확인해야 한다. 개인정보·피부 타입·리포트 ID·회원/게스트 ID를 외부 서브태그로 전송하지 않는 기존 규칙을 유지한다.

## 실상품 자료 형식

저장소에는 비어 있는 `data/affiliate-products/manifest.template.json`만 제공한다. 허위 실상품·브랜드·전성분·이미지·제휴 URL은 적재하지 않는다. 실제 자료 파일은 저장소 밖에 보관한다. 루트는 `version: 1`, `products` 배열이며 상품은 아래 필드를 갖는다.

| 필드                                                    | 내용                                                                                    |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `id`                                                    | 운영자가 고정해 관리하는 UUID. 같은 ID의 다른 내용을 덮어쓰지 않음                      |
| `brandName`, `productName`                              | 출처와 용량/제품 버전을 확인한 표시명                                                   |
| `category`                                              | TONER, AMPOULE, CREAM, SUNSCREEN                                                        |
| `tier`                                                  | PRIMARY 또는 SECONDARY                                                                  |
| `suitableBaumannTypes`                                  | 기존 16개 코드 중 명시적 배열. ALL/비표준 태그를 임의 확장하지 않음                     |
| `fullIngredients`, `keyIngredients`                     | 공식 표기를 확인한 전성분 문자열과 대표 성분 배열. 단순 태그만으로 전성분을 만들지 않음 |
| `affiliateBaseUrl`, `affiliatePlatform`                 | 승인 계정에서 발급받은 원래 링크와 설정의 플랫폼 식별명                                 |
| `thumbnailUrl`                                          | 검토한 `/catalog-assets/*.webp` 경로 또는 null. 외부 이미지 URL은 수집/대입하지 않음    |
| `review.sourceUrl`, `review.checkedAt`                  | 확인한 공식 자료 HTTPS URL과 ISO 날짜/시간. 미래 일자는 거절                            |
| `review.contentReviewed`, `review.imageRightsConfirmed` | 운영자가 확인했음을 true로 선언. 이미지가 없으면 null 사용을 확인한 것으로 기록         |

최대 128개, 4MiB 파일을 처리한다. 최소 8개 및 각 카테고리에 주력·대체가 모두 있어야 로컬 등록이 가능하다. 중복 ID·같은 링크·비인가 링크·일부 치료 단정 문구·누락된 출처/검토 확인을 거절한다. 이 검증은 글자/형식·운영자 선언 확인이며 원문을 자동 대조하거나 제품 효능·개인 적합성·이미지 권리를 독립적으로 보증하지 않는다. 전성분 언어/별칭과 추천 성분 매칭도 실제 자료 등록 시 함께 검토해야 한다.

## 미리보기와 로컬 적재

```sh
npm run products:import -- /tmp/miruvia-products.json
npm run products:import -- /tmp/miruvia-products.json --apply
```

첫 명령은 DB를 열지 않고 형식·설정·카테고리 수와 파일 SHA-256만 출력한다. 원본 링크/파트너 ID/상품별 출처 값은 출력하지 않는다. 준비가 안 된 빈 템플릿은 `readyForLocalImport: false`와 종료 코드 1이 정상이다.

`--apply`는 기존 개발 DB 보호기를 사용해 localhost/127.0.0.1의 sikin_dev/sikin_test:55432에서만 허용한다. 원격 DB에 쿼리하지 않는다. 전체 배치 검증 뒤 advisory lock과 트랜잭션 안에서 신규 상품만 **isActive=false, status=UNAVAILABLE**로 저장한다. 같은 내용의 기존 ID는 갱신 시각·활성 상태까지 보존한다. 한 ID라도 내용이 충돌하면 새 상품 생성도 모두 취소한다. SOURCE 검토 파일/해시는 운영자가 함께 보관해야 하며 새로운 출처 테이블을 만들지는 않았다.

API의 AMPOULE/SUNSCREEN은 기존 DB의 SERUM/SUNCARE로 변환한다. 기존 Product/추천/302 경로·오류 복구·제휴 고지 및 URL 허용 검사기를 재사용했다. 가격·새 스키마·별도 중계 API·수동 임상 적합성 점수는 추가하지 않았다. 일반 사용자나 관리자용 공개 쓰기 API도 만들지 않았다.

도구는 신규 상품을 활성화하거나 기존 활성 상품을 끄지 않는다. CATALOG_LIVE_ENABLED도 바꾸지 않는다. 따라서 원래의 체험 모드와 구매 기본 잠금을 유지하며, 운영 DB 쓰기나 공개 배포 명령으로 사용할 수 없다.

## 남은 외부 확인

1. 사용할 제휴 플랫폼 계정의 승인과 실제 트래킹 ID·발급 링크를 확보한다.
2. 4개 카테고리 주력/대체 최소 8개 상품의 공식 전성분·표시·이미지 사용권·재고/판매처 및 실제 발급 링크를 확인한다.
3. 제공자의 최신 트래킹/서브태그/서명 정책을 대조해 기존 쿼리 추가와 호환되는지 검증하고, 필요하면 해당 제공자에 한정해 빌더를 보완한다.
4. 실제 제휴처 이동과 파트너 귀속을 확인한 뒤, 별도 운영 반영 단계에서 상품/구매 연결을 활성화한다. 운영 전환은 이번 범위가 아니다.

현재는 원래 스펙의 실제 계정 발급·실상품 8개·제공자 이동 인수 기준이 미충족이므로 보드 review 상태를 유지한다. 임의 ID/발급 URL을 채워 done으로 표시하지 않는다. 기존 환경은 보존하고 `8b4c542` 원본 미복구 기록도 유지한다.

## 검증 기록

- 단위 테스트 285개 통과. 잘못된 출처 URL 처리 보완 후 관련 단위 검사 3개도 다시 통과했다.
- 최종 전체 DB 테스트 184개 통과. 가상 입력 8개를 이용한 신규 비활성 적재·SERUM/SUNCARE 변환·재실행 시 갱신 시각과 기존 활성 상태 보존·충돌 시 전체 취소·원격 DB 차단을 확인하고 테스트 데이터는 정리했다. 실제 상품을 적재하지 않았다.
- 최초 전체 DB 실행은 기존 시술 seed 보존 테스트가 순서 없는 findMany 두 결과를 비교해 실패했다. 양쪽에 ID 정렬만 명시한 뒤 동일 필드 전체 비교를 유지했으며 최종 전체 실행을 통과했다. 시술 데이터나 화면 정렬은 변경하지 않았다.
- lint, typecheck, 프로덕션 build, 변경 파일 Prettier 및 `git diff --check` 통과. UI·기존 중계 동작은 변경하지 않아 브라우저 검사를 새로 실행하지 않았다.
- 실제 미등록 환경에서 `npm run affiliate:check`와 빈 템플릿 미리보기의 종료 코드 1 및 준비 안 됨 표시를 확인했다. 이 결과는 예상한 안전 동작이며 실제 제휴 검증 성공으로 바꾸지 않았다.
- 실제 계정/파트너 ID/상품 URL은 설정·발급하지 않았고, 운영 DB 쓰기·구매 활성화·공개 배포·환경 게시·Git push는 수행하지 않았다.
