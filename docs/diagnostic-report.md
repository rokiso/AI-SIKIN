# 진단 리포트 오케스트레이터

ign8t 작업: `a9f84709-c81f-4c6e-b2a5-53703fca46e2` (2026-11-18).

## 동작

문진 완료 후 **피부 리포트 보기**를 누르면 저장된 응답을 서버에서 다시 계산합니다. 사진이 있고 실제 AI 연결을 명시적으로 켠 경우에만 기존 서버 전용 AI 게이트웨이를 호출합니다. 사진 보관소 재검증과 AI 요청에 합산 8초의 예산을 주며, 사용 불가·시간 초과·응답 검증 실패는 문진 기반 결과로 전환합니다. 화면에 사진 AI를 적용하지 않았다는 사실을 표시합니다. 실제 공급자 호출 없이도 문진 리포트를 이용할 수 있습니다.

문진 점수 비중은 `1 - 0.4 × 사진 신뢰도`, 사진 비중은 `0.4 × 사진 신뢰도`입니다. 신뢰도는 0~1이며 문진 비중은 최소 60%입니다. 시각 유분 힌트는 DRY=0, NORMAL=50, OILY=100으로 환산합니다. 나머지 시각 축은 게이트웨이의 외관 참고 점수입니다. 결합 후 반올림하고 각 축의 50점 이상 여부로 기존 16개 표준 코드를 정합니다. 숫자는 건강 등급이나 의료 측정값이 아닙니다.

기존 `DiagnosticReport`와 고유 sessionId, 불변 트리거를 재사용합니다. 새 테이블·운영 마이그레이션은 없습니다. 원자적 트랜잭션으로 리포트 생성과 세션 COMPLETED를 함께 저장합니다. 화면에는 한국어 설명을 사용하고, 산식이 없는 임의의 종합점수는 생성하지 않습니다 (`overallScore: null`).

## API와 권한

- `POST /api/v1/diagnostics/analyze`: `{ sessionId: UUID }`. 완료 시 HTTP 200, `data`에 스펙의 리포트 필드와 `status: COMPLETED`, `source`가 포함됩니다. 같은 세션의 완료 요청은 기존 리포트를 반환합니다.
- 동시 분석 중이면 HTTP 202, `{ success: true, data: { status: ANALYSIS_PENDING, sessionId } }`. 화면이 제한된 시간 동안 재확인하며 실패 시 같은 세션으로 다시 시도할 수 있습니다.
- `GET /api/v1/diagnostics/reports/[reportId]`: 본인 리포트의 공개용 프로젝션만 반환합니다. 감사 메타데이터·이미지 주소·키는 응답에 포함하지 않습니다.
- `/diagnostic/result/[reportId]`: 서버에서 동일한 소유권을 검사합니다. 레이더 차트·성분별 참고 설명·면책 안내·보관함/로그인 액션을 제공합니다. 보관함 상세에서도 전체 리포트로 이동할 수 있습니다.
- 실제 DB 회원 세션 또는 서명된 HttpOnly 게스트 증명을 확인합니다. 원시 게스트 ID 헤더는 인증 수단이 아닙니다. 회원에게 이전된 세션은 이전 게스트가 읽을 수 없습니다. 타인 접근 403, 없는 리포트 404, 잘못된 입력 400, 인증 없음 401, 한도 초과 429입니다. 응답은 private, no-store입니다.
- 소유자별 advisory lock으로 1시간 최대 3개의 새 분석을 제한합니다. 완료된 요청 재확인은 한도를 소비하지 않습니다. 네트워크 호출 중 DB 트랜잭션을 열어두지 않습니다. 30초가 지난 중단된 ANALYSIS_PENDING은 다시 획득할 수 있고, 획득 시각과 최종 소유권을 재검사해 늦게 끝난 이전 작업이 새 결과를 덮어쓰지 못하게 합니다.
- 실제 사진은 완료된 업로드의 ETag·크기·형식·AES256 메타데이터를 다시 확인한 뒤 전달합니다. 실패하면 사진을 공급자에게 전송하지 않습니다. 장치 안의 미리보기 사진은 분석 API로 보내지 않습니다.
- 감사 기록은 기존 게이트웨이의 비동기 저장과 Next `after()`를 연결합니다. 불변 리포트의 `auditStatus: PENDING`은 저장 확정을 의미하지 않습니다.

## 스펙과 저장소 차이

예시의 신규 Prisma 모델, `summary`, JSON 성분 컬럼, 접두사 붙은 ID 대신 현재 모델의 `summaryText`, 문자열 배열, UUID를 유지합니다. 이미 있는 `lib/ai/multimodal.ts`를 사용하고 별도 클라이언트를 중복 생성하지 않습니다. 면책 컴포넌트의 실제 위치는 `components/layout`입니다. 스펙의 조용한 폴백 문구 대신 현행 visible-errors 지침에 따라 문진 기반 전환을 드러냅니다. 영어 타입코드 숨김과 임의 종합점수 미생성이라는 기존 결정을 유지합니다.
