# 서버 전용 멀티모달 AI 연결 기반

## 재구현 범위와 복구 상태

ign8t 작업 `f0d9913a-c576-4bca-b384-e711b4183dce`의 ready 스펙과 이전 구현 노트에 근거해 다시 작성했습니다. 이전 노트에는 OpenAI/Gemini, 전체 8초 제한·1회 재시도, 감사 테이블, 관리자·시스템 전용 점검 API, 실제 호출 기본 OFF 및 dry-run 기본 true가 기록되어 있습니다.

원 커밋 `8b4c542`는 **아직 복구되지 않았습니다**. 이번 구현을 원 커밋의 객체 복구나 바이트 단위 복원으로 간주하지 않습니다. 기존 환경은 삭제·초기화하지 않으며, 접근이 복구되면 원 커밋을 별도로 보존·대조해야 합니다. 검증된 테스트 모드 수정은 로컬 커밋 `a556b0f`에 먼저 저장했습니다.

이 작업은 후속 진단 오케스트레이터가 호출할 연결 기반입니다. 최종 바우만 판정·리포트 UI·문진 가중치 결합·기존 스냅샷 AI 교체는 하지 않습니다. 기존 사진 체험 모드와 일반 관리 안내도 유지합니다.

## 서버 설정

| 변수 | 동작 |
| --- | --- |
| `AI_LIVE_ENABLED` | 정확히 `1`일 때만 외부 AI 호출 허용. 기본 OFF |
| `AI_PROVIDER` | `OPENAI` 또는 `GEMINI`. 생략하면 `OPENAI`지만 키·모델을 대신 채우지 않음 |
| `AI_API_KEY` | 서버 전용 공급자 키. 클라이언트 공개 변수에 넣지 않음 |
| `AI_MODEL_NAME` | 필수 명시. 구식 모델을 기본값으로 강제하지 않음 |
| `AI_REQUEST_TIMEOUT_MS` | 기본 8000, 양의 정수. 8000 초과는 8000으로 제한 |
| `AI_HEALTHCHECK_TOKEN` | 선택적 시스템 인증. 임의의 base64url/hex 32~256자. 기본 토큰·localhost 우회 없음 |

`.env.example`에는 이름과 비밀이 아닌 자리표시자만 있습니다. 실제 값은 서버의 비밀 설정에 입력하고 소스·로그·채팅에 기록하지 않습니다. AI 설정은 클라이언트 초기화 시 검증하므로 AI 미설정 때문에 기존 앱 전체 시작을 막지 않습니다. 이 재구현에서 실제 키를 생성·발급·저장하거나 유료 요청을 실행하지 않았습니다.

## 호출 계약

`lib/ai/multimodal.ts`의 `callMultimodalAiWithTimeout`은 스펙의 이미지·MIME·문진 점수 입력을 검증합니다. 이미지는 10MiB 이하의 시그니처가 맞는 JPEG/PNG/WebP base64 또는 설정된 S3 보관소의 HTTPS 주소만 허용합니다. 임의 호스트·사용자 정보·별도 포트·리다이렉트는 허용하지 않습니다. 주소 입력은 서버가 제한된 크기로 읽어 base64로 전달하며 AI 키를 이미지 서버로 보내지 않습니다.

OpenAI는 Responses API와 `store:false`·엄격 JSON 스키마를 사용합니다. Gemini는 `generateContent`, `inlineData`, JSON 스키마와 `x-goog-api-key` 헤더를 사용하며 URL 쿼리에 키를 넣지 않습니다. 추가 의존성 없이 저장소의 Node.js fetch를 사용합니다. 응답 구조·점수 범위·토큰 수치·통제된 출력 형식을 검사하고, 잘못된 응답을 정상 결과로 대체하지 않습니다.

이미지 조회, 외부 응답 본문 읽기, 250ms 백오프 및 최대 1회 재시도는 **하나의 8초 이하 기한**을 공유합니다. 429/5xx 및 네트워크 오류만 재시도하며 인증 오류·잘못된 출력은 재시도하지 않습니다. 외부 fetch가 abort를 무시하더라도 전체 기한의 Promise 경합으로 반환합니다. 실패 시 `AiTimeoutError`/`AiGatewayError`의 안전한 코드와 `fallbackTriggered:true`를 전달합니다. 규칙 기반 최종 리포트를 이 기반 모듈이 임의로 만들지는 않습니다.

## 감사 로그

추가 마이그레이션 `20261118000000_ai_inference_audit`는 `ai_inference_audit_logs`와 `AiInferenceStatus`를 만듭니다. 기존 6개 마이그레이션은 수정하지 않았으며, 로컬 개발 DB에만 적용했습니다.

실제 공급자 호출의 성공·실패·시간 초과마다 UUID, 선택적 내부 진단 세션 ID, 공급자·모델, 프롬프트 템플릿 SHA-256, 실제 지연·토큰 수·상태 및 통제된 오류 코드만 기록합니다. 이미지·서명 URL·키·원문 프롬프트·원문 공급자 오류는 저장하지 않습니다. 잘못된 입력·설정·비활성 상태처럼 공급자를 호출하지 않은 요청에는 추론 기록을 만들지 않습니다.

반환된 `auditWrite` Promise를 Next.js `after()`에서 유지합니다. 점검 API는 이를 등록하고 HTTP에 `auditStatus:"PENDING"`을 명시합니다. 따라서 응답 시점에 저장 성공을 주장하지 않습니다. DB 저장 실패는 비밀 없는 서버 로그와 `FAILED` 결과로 구분하며, AI 결과를 성공한 감사 저장으로 위장하지 않습니다. 이후 호출자도 같은 방식으로 Promise 수명을 유지해야 합니다.

## 비공개 점검 API

`POST /api/v1/diagnostics/ai-healthcheck`만 제공합니다. 응답은 `private, no-store`입니다.

- 살아 있는 DB 세션의 ADMIN과 같은 출처 요청, 또는 강한 `x-system-healthcheck-token`을 요구합니다. 원시 사용자 ID·역할 헤더나 localhost 주소를 신뢰하지 않습니다.
- 인증 주체당 분당 10회로 제한합니다. 제한은 현재 인스턴스 내 안전장치이며 **다중 인스턴스 전역 제한은 미완료**입니다. 실제 운영 연결 전에 공유 제한 계층이 필요합니다.
- JSON 본문은 8KiB 이하, 모의 이미지는 4096자 이하의 검증된 data URL만 받습니다. 클라이언트가 임의 외부 URL을 입력할 수 없습니다.
- 본문 `{}` 또는 `{"dryRun":true}`가 기본입니다. 설정 검사만 수행하며 `status:"CONFIGURED"`, `remoteChecked:false`를 반환합니다. 실제 공급자 정상 연결을 주장하는 `HEALTHY`와 구분합니다.
- `{"dryRun":false}`도 서버의 `AI_LIVE_ENABLED=1` 없이는 외부 호출을 켜지 못합니다. 누락된 이미지는 내장된 합성 1픽셀 PNG를 사용합니다. 실제 사진이나 최종 진단 결과로 해석하지 않습니다.
- 실제 모의 점검이 성공했을 때만 `HEALTHY`와 안전한 외관 분류 일부를 반환합니다. 실패는 400/401/403/429/502/503/504로 구분하며 공급자 키나 오류 본문을 노출하지 않습니다.

이는 이전에 승인된 안전 기본값을 유지한 것으로, 최초 스펙의 약한 기본 토큰·dry-run 기본 false·dry-run도 HEALTHY라는 예시는 사용하지 않습니다.

## 검증과 남은 연결 확인

모의 공급자 단위 검사와 실제 로컬 PostgreSQL 검사로 양 공급자 직렬화, 8초 전체 기한, 재시도, 출력/이미지 검증, ADMIN·시스템 인증, 출처 검사, 요청 제한, 비밀 비노출, 감사 성공·오류·시간 초과 및 저장 실패 구분을 검사했습니다.

HTTP 검사는 임시 프로세스의 테스트용 설정과 합성 이미지만 사용하고 `.env`에는 쓰지 않았습니다. 응답에 공급자 키·시스템 토큰이 포함되지 않음을 검증한 후 해당 서버를 종료했습니다. 사용자 화면이나 진단 데이터 생성 흐름은 변경하지 않았습니다.

실제 공급자 키와 모델은 현재 주입되지 않았습니다. 공식 공급자 문서 접근도 환경 프록시에서 403이어서, 실제 키·선택 모델의 원격 구조화 출력 호환성은 **미검증**입니다. 모의 성공을 실연결 성공으로 표시하지 않습니다. 실제 외부 호출, 공개 배포, 환경 게시, 운영 마이그레이션은 수행하지 않습니다.

나중에 실제 연결을 검증할 때는 선택한 공급자의 `api.openai.com` 또는 `generativelanguage.googleapis.com`에 대한 네트워크 허용과 비밀 설정을 먼저 확인해야 합니다. 실연결 및 다중 인스턴스 전역 제한 검증이 남으므로 ign8t의 원 AI 기반 작업은 review로 유지합니다.
