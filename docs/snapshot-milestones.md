# 스냅샷 3일·7일 연속 기록 리포트

ign8t 작업 `33926934-eef2-4556-8084-97719539714d`의 ready/non-stale 스펙과 마스터 스펙(context 65)을 2026-11-24 KST에 읽고 구현했다. 기존 `lib/snapshot`, 검증된 회원 세션, S3 300초 조회 서명, 네이티브 dialog와 디자인 토큰을 재사용한다. 스펙 예시의 `modules/snapshot`, `req.user.id` 대신 저장소의 실제 경로와 `requireSnapshotMember`를 사용한다.

## 기록과 발급

- 기존 한국 시간 날짜 유틸리티를 사용한다. `record_date`는 시간대 없는 DB DATE로 처리하고 서버 로컬 날짜를 사용하지 않는다.
- 오늘 작성했다면 오늘부터, 아직 작성하지 않았다면 어제부터 연속 기록을 센다. 하루가 비면 초기화한다. 최장 기록은 전체 기록의 연속 구간에서 계산한다. 미래 날짜는 현재/최장 계산에서 제외한다.
- 한 구간의 정확히 3일째와 7일째에만 발급한다. 두 리포트 모두 해당 구간 첫날이 기준이며 8일째부터 매일 추가 발급하지 않는다. 이후 새 구간에서는 다시 달성할 수 있다.
- 스냅샷 저장과 리포트 생성은 기존 기록일 잠금과 달성 기능의 사용자 단위 잠금 및 단일 DB 트랜잭션 안에서 실행한다. 한국 시간의 이웃한 날짜 요청이 겹쳐도 앞선 저장이 완료될 때까지 기다려 연속 기록이 누락되지 않게 한다. `(userId, milestoneType, achievedDate)` 유니크 제약으로 중복을 막고, 완료 요청 재시도에는 기존 리포트를 반환한다. 리포트 발급 오류는 스냅샷·업로드 완료 처리도 롤백한다.
- 새 테이블은 사용자 및 시작/달성 스냅샷을 FK로 참조하며 삭제를 cascade한다. 기존 실제 회원 탈퇴 처리에서도 해당 사용자의 리포트가 삭제되고 다른 회원의 리포트는 보존된다. 탈퇴 기능을 새로 활성화하지 않는다.

## 피부 지표의 의미

기존 `GENERAL_GUIDANCE` 스냅샷의 BALANCED 기본값은 AI 분석값이 아니다. 따라서 스펙의 지표 필드를 nullable로 확장하고 분석이 없는 쪽은 null, 비교 결과 `improved`는 null로 반환한다. 화면에는 ‘비교 자료 없음’을 표시하며 숫자나 개선 결과를 만들어 내지 않는다. AI 기록끼리는 보습·진정 레벨 상승, 유분의 BALANCED 방향 이동을 비교한다.

비교는 사진 외관에 대한 AI 참고 분류이며 수분 측정, 피부 장벽 개선 또는 관리 효과의 증거가 아니다. 요약은 저장된 두 사진의 분류 유무를 설명하는 결정적 문구로 생성한다. 추가 AI 호출·비용은 없으며 의료진 검수나 치료 효과를 주장하지 않는다.

## API와 화면

- `GET /api/v1/snapshots/streak`: 현재·최장 일수, 마지막 기록일, 당일 기록 여부, 다음 목표(3/7일), 최신 달성 리포트 메타데이터.
- `GET /api/v1/snapshots/milestones?cursor=<uuid>`: 본인 리포트 최신순 20개, 다음 페이지 커서. 메타데이터만 반환하며 서명 URL을 포함하지 않는다.
- `GET /api/v1/snapshots/milestones/[milestoneId]`: 본인 리포트와 두 사진 소유권 확인 후에만 300초 S3 조회 URL을 발급한다. 비회원/만료·삭제 세션 401, 타인 리포트 403, 없는 리포트 404, 잘못된 UUID/쿼리 400. 응답은 기존 표준 JSON 봉투와 `private, no-store`를 사용한다.
- 기존 스냅샷 POST 응답에 `data.milestone` 메타데이터를 추가한다. 기존 응답 필드는 유지한다.
- `/snapshot`에서 새로 달성한 리포트를 자동 표시한다. `/snapshot`과 `/mypage`에서 현재/최장 배지, 최신 리포트, 페이지 단위 보관함을 제공한다. 모달은 로딩·조회 실패/재시도·사진 만료/재조회·지표 없음 상태를 지원하고 Escape/닫기 후 원래 버튼으로 초점을 돌려준다.

## 적용과 검증

새 마이그레이션은 `20261124000000_snapshot_milestones`다. 기존 마이그레이션은 수정하지 않았다. 로컬 개발 DB에만 추가 적용했으며 운영 DB는 변경하지 않는다. 운영은 기본 OFF인 `SNAPSHOT_MILESTONES_ENABLED`를 사용한다. 운영 스키마와 기존 스냅샷 저장·조회 및 신뢰할 수 있는 스토리지 설정을 검증한 뒤 별도로 1로 활성화해야 한다. OFF에서는 UI를 숨기고 기존 스냅샷 쓰기가 새 테이블에 접근하지 않는다. 인증된 새 API 요청에는 준비 중 503을 반환한다. Playwright 소유 로컬 서버는 명시적으로 ON을 사용한다.

단위/DB 검사는 KST 자정·누락·윤년/연말·최장·3/7일 발급·중복 완료·트랜잭션 롤백·자료 없음·페이지 구분·비회원/타인/손상된 사진 참조·탈퇴 cascade·운영 OFF 호환성을 확인한다. 브라우저 검사는 320/390/1280px에서 달성 모달, 마이페이지 재조회, 접근성, 초점 복원과 로딩/오류/빈 상태를 확인한다. 브라우저에서는 합성 사진과 로컬 DB fixture로 업로드 완료를 대체하고 실제 조회 API를 통과한다. 실제 스토리지 업로드·AI 분석·장기간 피부 변화를 검증했다고 표시하지 않는다. 기존 업로드/저장 핸들러와 발급 트랜잭션은 별도의 DB 통합 테스트로 확인한다.

이 작업에서 공개 배포나 환경 게시를 수행하지 않는다. 원래 `8b4c542`는 미복구 상태이며 기존 환경을 보존한다. 최종 검사 결과는 작업 보드와 저장소 밖 검증 로그에 남긴다.
