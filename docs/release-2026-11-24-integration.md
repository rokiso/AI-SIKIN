# 2026-11-24 통합 작업 공개 배포

사용자가 `2df66b3` 통합 결과의 공개 배포를 요청했다. 대상은 기존 GitHub 저장소 `rokiso/AI-SIKIN`의 main과 Git 연동된 https://miruvia.vercel.app 이다. 공개 기준 main은 `224b8c85b9aa496031e1ec30819f1ca1f2502e35`이며, force push 없이 두 채팅의 이력을 보존한다.

## 포함 범위

- 260건·102조건의 시술 가격과 조건 선택, 별도 공개 가격표 44건·37옵션. 서로 다른 조건이나 두 자료군을 같은 평균에 섞지 않는다. 전국 평균·의료진 검수 완료로 표시하지 않는다.
- 복원한 촬영/앨범의 업로드 전 품질 검사와 재시도 안내, AI 실패 시 문진 폴백과 안내, 제휴 링크 점검 구현.
- 기존 3일·7일 기록 마일스톤 구현과 운영 기본 비활성 설정 유지.

## 운영 DB를 변경하지 않는 배포 호환 처리

이번 환경에는 Vercel 관리 토큰과 운영 DB 접속 정보가 없으며 `api.vercel.com`도 허용 목록에 없다. 운영 migration 적용 여부를 확인하거나 변경했다고 주장하지 않는다. 기존 Git 연동으로 공개 코드를 갱신하며, 운영 기능의 활성화와 구분한다.

`DiagnosticReport`의 추가 컬럼은 기존 Prisma 조회와 저장에도 영향을 준다. 새 `DIAGNOSTIC_FALLBACK_STORAGE_ENABLED`는 운영에서 명시적으로 `1`을 설정하기 전까지 OFF다. OFF에서는:

1. 공통 명시적 select로 기존 컬럼과 JSON 감사 메타데이터만 읽는다. 분석 요청, 결과 재조회, 완료된 SSE 조회가 같은 선택을 사용한다.
2. Prisma가 INSERT 시 생략된 스키마 기본값까지 제공하므로, 기존 컬럼만 지정한 parameterized SQL을 동일한 소유권·멱등성 트랜잭션 안에서 사용한다. 원자적 세션 완료와 리포트 저장, 기존 배열/JSON 계약을 유지한다.
3. 폴백 여부·사유는 기존 `ai_audit_metadata`에 저장하고 리포트 안내에 반영한다. 새 컬럼을 사용하지 않아도 문진 리포트 생성과 장애 안내는 유지된다.
4. ON에서는 원래 Prisma 쓰기와 새 감사 컬럼을 사용한다. 향후 ON 전에는 운영 DB 백업, pending migration 적용 및 검증이 필요하다. 개발용 `db:migrate`를 운영 URL에 연결하지 않는다.

따라서 이전 통합 기록의 “새 컬럼 migration 후 코드 배포 필요” 제한은 **컬럼 저장 OFF인 이번 호환 배포**에는 적용되지 않는다. 데이터베이스 준비가 필요한 안전 상세·마일스톤·제휴 스케줄러는 이번 작업에서 활성화하지 않는다. 실제 AI·S3·OAuth·제휴 계정, 회원 탈퇴·약관 설정도 새로 활성화하지 않는다.

## 검증

- 새 폴백 컬럼이 없는 초기 4개 migration만 적용한 임시 로컬 DB에서 게스트·회원의 기본 화면, 설문 저장/재전송, 진단 생성/재조회/중복 요청, 완료 SSE, 과거 동의 이전을 검증했다. 운영 DB는 사용하지 않았다. 임시 DB만 검사 후 정리했다. [호환 결과](release-2026-11-24-integration-compatibility.json)를 참조한다.
- 일반 migration 적용 DB에서는 컬럼 저장 ON과 OFF를 모두 검사한다. OFF에서도 JSON 폴백·성분 배열·재조회·동일 요청 결과가 유지되는 회귀 테스트를 추가했다.
- CI의 시술 가격 준비 경로를 최신 2026-11-24 자료로 맞췄다.
- 기존 체크리스트 단위 테스트의 간헐 실패는 대체 textarea 표시와 selection effect 완료 사이의 경합이었다. 선택 상태가 완료될 때까지 기다리도록 테스트만 수정했고 복사 UI는 변경하지 않았다.
- lint, format:check, typecheck, build 통과. 단위 301개·DB 209개·브라우저 143개 통과, 데이터가 존재해 적용되지 않는 빈 안내 시나리오 2개는 의도된 skip이다. 모의 AI·저장소·OAuth core 진단 4개도 통과해 테스트 총 657개가 통과했다. 배포 SHA와 실제 공개 확인 결과는 저장소 밖 배포 영수증에 기록한다.

## 저장 및 배포 확인

검증한 커밋의 전체 이력 bundle을 먼저 만들고 빈 저장소에서 복원 HEAD와 fsck를 확인한다. 개인 MCP 설정과 `.env`를 Git에 포함하지 않는다. main non-force push 후 원격 SHA와 실제 공개 시술 JSON·기본 화면·새 헬스체크 API의 인증 거부 응답을 확인한다. Vercel 콘솔 Ready 확인과 실제 공개 응답 확인은 구분한다.

기존 환경은 삭제하지 않는다. `8b4c542`는 여전히 미복구이며, `6d1dcc5` 복원과 동일시하지 않는다. 환경 설정 초안의 저장·게시는 이번 앱 공개 배포와 별개이며 임의로 수행하지 않는다.
