# 비회원 세션 발급과 로그인 데이터 이관

2026-11-19, ign8t 작업 `dd823cc9-45c8-480a-8c54-acedb76e34aa`. 새 API 키로 프로젝트 → 마스터 스펙 → 다음 작업 순서를 확인하고 ready 작업 전문을 읽었다. 기존 구현을 재사용하며 누락된 계약과 안내를 보완했다.

## 게스트 발급 계약

`POST /api/v1/auth/guest-session`은 같은 출처의 본문 없는 요청만 받는다. UUIDv4와 서버 HMAC 소유권 증명을 함께 발급한다. 쿠키 이름은 기존 `x-guest-session-id`, `sikin_guest_proof`를 유지한다. 운영에서 HttpOnly/Secure/SameSite=Lax/Path=/, 최초 유효기간은 30일이다.

- 최초 발급은 201, 유효한 ID와 증명을 다시 사용하면 200.
- 응답은 `{ success: true, data: { guestDeviceId, createdAt, expiresInSeconds } }`. 증명·서명 키는 본문에 반환하지 않는다.
- 재호출해도 최초 발급 시각과 ID를 유지하고, 남은 유효기간만 반환한다. 새 30일을 덧붙여 기존 증명을 무기한 연장하지 않는다.
- 만료·위조·불일치 증명은 새 UUID와 증명으로 교체한다. 클라이언트가 준 UUID에 서버 서명을 붙여 주지 않는다.
- DB에서 확인된 회원은 409 `GUEST_SESSION_NOT_REQUIRED`, 본문이 있으면 400, 다른 출처는 403이다. 토큰 후보가 있어도 DB 확인 없이 회원으로 인정하지 않는다.
- 최초 페이지 요청은 기존 Next.js `proxy.ts`가 자동 발급한다. 게스트 발급 API도 프록시를 거치므로 실제 최초 요청 응답이 200일 수 있으며, 스펙의 200/201 계약에 부합한다.

쿠키의 유효기간은 접근용 임시 식별자의 기간이다. 사진 보관 기간이나 자동 삭제 기간을 의미하지 않는다. 별도 기록된 보관·삭제 미구현 사항과 비활성 약관을 변경하지 않았다.

## 단일 로그인 트랜잭션

`lib/auth/migrationService.ts`의 `migrateGuestDataToUser(tx, { guestDeviceId, targetUserId })`를 OAuth의 기존 `provisionSession` 트랜잭션에서 호출한다. 서명된 게스트 증명, OAuth state/PKCE 및 실제 제공자 프로필 검증은 기존 인증 파이프라인이 담당한다. 사용자/계정 생성, 진단·업로드 세션 이관, 동의 소유권 연결, 회원 세션 저장을 서로 다른 트랜잭션으로 분리하지 않는다.

- 동일 `guest:<uuid>` 트랜잭션 advisory lock을 유지한다.
- 진단 세션과 이미지 업로드 세션 모두 `guestDeviceId`가 일치하고 `userId IS NULL`인 행만 갱신한다.
- 리포트는 진단 세션 소유권을 따라가며, 내용·파일 키·기존 소유자는 변경하지 않는다.
- 같은 요청을 다시 처리하거나 경쟁 계정이 접근해도 이전 소유권을 덮어쓰지 않는다. 두 테이블은 한 계정으로 수렴한다.
- 반환값은 `migratedDiagnosticSessions`, `migratedImageSessions`. 기존 `migratedSessionsCount`는 진단 세션 수로 유지해 기존 클라이언트와 호환된다.
- 로그인 처리 후에도 기존 게스트 증명으로 회원 소유 리포트를 읽을 수 없다. 리소스 접근 인가는 각 서버 엔드포인트에서 별도로 수행한다.

## 쿠키와 완료 안내

콜백 성공 응답은 기존 회원 세션 쿠키를 발급하고 게스트 ID·증명·OAuth state 쿠키를 만료시킨다. 프록시도 DB에서 회원 세션을 확인하면 새 게스트를 만들지 않으며 남아 있는 게스트 쿠키를 만료시킨다. 만료·철회된 회원 토큰은 실제 조회 결과에 따라 게스트로 전환한다. DB 오류를 정상 로그아웃으로 숨기지 않는다.

실제 이관이 1건 이상이면 짧은 HttpOnly 완료 표시 쿠키를 남긴다. 서버에서 인증된 회원에 한해 도착 페이지 상단에 `이전 진단 이력이 회원 계정으로 안전하게 연결되었습니다.` 안내를 3초 동안 표시한다. 닫기 버튼은 44px이며, 이 표시를 인증·권한·이관 증명으로 사용하지 않는다. 비회원이 표시 쿠키를 임의로 붙여도 안내가 나타나지 않는다.

## 스펙과 기존 계약의 조정

- 설치된 Next.js 16의 `proxy.ts`와 기존 OAuth 라우트를 재사용한다. Prisma 테이블이나 OAuth 통신을 새로 구현하지 않았다.
- 스펙 위험 대응에 있는 raw UUID 헤더/로컬 스토리지 대체는 always-on 서버 인가 규칙과 충돌한다. ID는 권한 증명이 아니므로 서명 검증을 유지한다. 쿠키가 차단되면 식별자 헤더만으로 이력을 복구하거나 이관하지 않는다.
- 실패 안내 중 `로그인은 완료되었으나...`는 단일 트랜잭션 롤백 규칙과 맞지 않는다. 로그인과 기록 연결 실패를 알리고 재로그인을 제공하며, 성공한 것처럼 표시하지 않는다. 이전 기록은 롤백으로 보존된다.
- 외부 카카오/구글 운영 자격증명과 실제 IDP 연결은 별도 OAuth 소유 작업의 범위다. 이번 검증은 스펙의 가상 제공자 콜백 계약을 사용하며, 실제 운영 로그인을 새로 활성화했다고 주장하지 않는다.

공개 배포·Git push·환경 게시·이전 환경 삭제는 이 작업에서 수행하지 않는다. 개인 MCP 키는 저장소 밖 0600 설정 파일에만 갱신한다. `8b4c542` 원본 복구 상태는 미해결로 유지한다.

## 검증 결과

- 전체 단위 테스트 244개, 실제 로컬 PostgreSQL 통합 테스트 152개 통과.
- 브라우저 기존 회귀 87개와 신규 4개 통과. 최초 신규 3개 실패는 NextURL의 loopback 주소 정규화와 테스트 Origin 불일치였으며, 기존 POST 테스트와 같이 `localhost`를 사용해 해결했다. 출처 검증은 완화하지 않았다.
- Google/Kakao 가상 제공자 콜백으로 실제 DB의 진단·업로드 소유권, 회원 쿠키 발급, 게스트 쿠키 만료, 이관 수를 확인했다. 재시도·경쟁 계정·후속 오류 시 롤백도 검증했다.
- 360px/1280px 화면을 직접 확인했다. 완료 안내 자동 닫힘, 44px 닫기 버튼, 가로 넘침 없음, Axe WCAG 검사 통과. 위조 안내 쿠키만으로 비회원에게 안내가 표시되지 않는다.
- production build, ESLint, TypeScript, 변경 파일 Prettier 및 `git diff --check` 통과.

외부 운영 OAuth 제공자에 대한 실제 로그인과 공개 배포는 이번 검증에 포함하지 않는다.
