## 요청 제한과 데이터 저장

새 slug API와 상세 SSR 진입에 분당 120회 제한을 적용한다. 서버리스 인스턴스별 메모리 대신 PostgreSQL의 전용 짧은 수명 카운터를 한 SQL로 갱신해 동시 호출을 직렬화한다. 121번째부터 429와 Retry-After를 반환한다. 카운터는 121에서 포화시켜 정수 오버플로를 방지한다.

기존 신뢰 IP 추출기와 운영자가 지정하는 CONSENT_TRUSTED_IP_HEADER를 재사용한다. 이 설정은 신뢰할 수 있는 인입 장치가 헤더를 덮어쓰는 배포에서만 사용한다. 설정/유효한 IP가 없으면 클라이언트의 임의 X-Forwarded-For를 믿지 않고 미식별 요청용 공유 한도를 사용한다. 이때 사용자별 제한이라고 주장하지 않는다. IPv6 표기는 정규화하며 원본 IP·사용자 ID는 카운터에 저장하지 않는다. 기존 서버 서명 키로 용도를 구분한 분 단위 HMAC을 저장한다. 만료 시각은 해당 분 이후 2분이며, 만료 행은 다음 요청의 SQL에서 정리한다. 별도 cron/강제 TTL 삭제를 배포했다고 주장하지 않는다.

기존 proxy의 쿠키/개인 응답 보호를 유지하므로 public s-maxage로 바꾸지 않았다. 데이터 원본이 published여도 요청 제한 저장소는 DB를 사용한다. DB 원본의 안전 내용은 현재 parent에 속한 행을 읽고, 기존 원리/가격 카탈로그 캐시는 재사용한다. 운영에서 새 테이블이 없거나 DB가 실패하면 제한을 우회하지 않고 503으로 처리한다.

신규 마이그레이션은 안전 가이드와 요청 제한 테이블 2개이며 검증된 로컬 DB에만 적용했다. `npm run procedures:seed`는 기존 10종을 보존한 뒤 안전 가이드를 원자적으로 추가한다. 기존 안전 행과 가격 관측은 덮어쓰지 않는다. 관리자/일반 사용자 수정 API는 만들지 않았다. 운영 반영에는 새 마이그레이션과 필요한 시드를 별도로 적용해야 한다.
