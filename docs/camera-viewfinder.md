# 가이드 카메라와 클라이언트 캡처

`/diagnostic`에서 카메라 촬영 모드와 기존 앨범 업로더를 전환합니다. 기본 전면 카메라와 후면 요청, 타원·눈/입·중앙 가이드, 촬영·다시 촬영·사진 확정, 권한 거부 시 앨범 복구를 제공합니다. 전면 화면은 거울처럼 표시하지만 캡처 픽셀을 임의로 뒤집지 않습니다. 카메라 전환은 브라우저의 facingMode 선호를 요청하며 실제 장치 선택은 휴대폰에서 확인해야 합니다.

기존 `isPhotoTestMode()`가 켜진 환경은 `LocalPhotoPreview`의 ‘가이드 카메라로 촬영’에서 같은 UI를 사용합니다. 이때 확정은 기기 내 미리보기만 수행하고 로그인·업로드 API·S3·AI를 호출하지 않습니다. 기존 휴대폰 기본 카메라 입력과 앨범 선택도 유지합니다.

## 처리 및 자원 수명

- `hooks/useCameraStream.ts`: audio=false, user/environment 선호 요청. 전환·끄기·문서 숨김·언마운트 시 모든 트랙을 중지합니다. 권한 응답이 화면 이탈 뒤 도착해도 반환된 트랙을 즉시 중지합니다.
- `lib/image/viewfinderCapture.ts`: 기존 `resizedDimensions`와 `ProcessedImageResult`를 재사용하고 긴 축 1280px 이하로 리사이징해 품질 0.85 JPEG를 생성합니다. 준비되지 않은 비디오는 거절하고 인코딩은 10초로 제한합니다. 실제 영상 프레임은 브라우저 방향을 따르며 EXIF가 없고, 앨범 파일의 EXIF 처리는 기존 업로더가 담당합니다.
- 원본·가공 사진을 localStorage나 IndexedDB에 저장하지 않습니다. object URL은 재촬영·모드 이탈·언마운트에 해제하고 캔버스 버퍼도 비웁니다. 취소 후 늦게 완료되는 캡처의 URL도 해제합니다.
- `OnCameraCaptureCompletePayload`는 processedImage, qualityMetrics와 선택적 uploadSessionId/s3Key를 제공합니다. 컴포넌트의 onCaptureComplete는 미리보기 확정 또는 업로드 완료 시 이를 전달합니다. URL 소유권은 컴포넌트에 있으므로 소비자는 화면 이탈 뒤 보관하거나 영구 저장하지 않아야 합니다. 기존 부모의 onUploadComplete는 저장소의 실제 업로드 인계 규격을 그대로 사용합니다.

## 품질 안내의 한계

카메라 촬영과 진단용 앨범 사진은 브라우저 안에서 최장 변 640px로 줄인 이미지로 검사합니다. Rec.601 평균 휘도 40 미만을 가장 먼저 안내합니다. 브라우저의 FaceDetector로 얼굴과 중심 위치를 확인하며, 지원하지 않거나 감지가 실행되지 않는 환경에서는 중앙 타원 내 YCbCr 픽셀 비율과 명암 차이를 이용해 얼굴 후보를 판단합니다. 라플라시안 분산 50 미만이면 흐림으로 안내합니다. 색상 기반 검사는 조명과 배경에 영향을 받는 근사값입니다.

사진이 기준에 미달하면 미리보기 생성과 업로드를 중단합니다. 카메라에서 다시 촬영하거나 앨범으로 바꿀 수 있으며, 앨범에서는 다른 사진을 고를 수 있습니다. Escape로 닫으면 원래 제어로 초점이 돌아갑니다. 통과한 사진은 기존 1280px 전처리와 10KB~10MB 파일 제한을 적용하고, 카메라 업로드는 기존 미리보기 확인 뒤에 시작합니다.

## 실제 업로드 모드

사진 확정 때 기존 `uploadDiagnosticImage`의 서명 URL → AES256 직접 PUT → ETag 완료 검증을 재사용합니다. 진행률과 중복 확정 방지, 전송 실패 재시도, 업로드 중 앱 메뉴 잠금은 기존 패턴을 따릅니다. 원래 백엔드나 스키마는 변경하지 않았습니다. 문진·AI 분석은 이 작업에 포함하지 않으며 사진 업로드 성공을 진단 결과로 표시하지 않습니다.

실제 S3·AI·소셜 로그인 연결은 기존 결정대로 보류했습니다. 공개 배포나 운영 DB 변경도 이번 작업에서 수행하지 않았습니다.

## 검증 범위

단위 검사는 휘도 40 경계·명암/흐림 분기·잘못된 버퍼, 권한 지연 후 언마운트·스트림 전환 정리를 검사합니다. 합성 Canvas MediaStream 브라우저 검사는 320px/1280px 가이드·키보드/접근성, 전후면 요청, 1280×960 JPEG 미리보기, 재촬영 URL 정리, 모든 트랙 종료, 권한 거부 앨범 복구, 저조도·흐림·얼굴 미검출 차단 및 재촬영과 앨범 대체 경로, 모의 S3 전송 실패 후 재시도를 검사합니다. 체험 모드에서는 POST/PUT/PATCH 요청이 없음을 별도 검사합니다.

실제 휴대폰 하드웨어·카메라 권한 UI·모바일 방향 전환·실제 S3 전송·안면 인식·피부 분석을 검증한 결과는 아닙니다. 전체 브라우저 검사는 기존 사진/로그인/쇼핑 화면을 포함합니다.
