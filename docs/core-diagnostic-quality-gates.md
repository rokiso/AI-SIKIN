## 통과하는 실제 앱 경로

1. 빈 브라우저에서 홈 → 진단으로 이동하여 실제 HttpOnly 게스트 식별자와 서명 증명을 발급받는다.
2. 사람이 없는 1280×1280 합성 JPEG를 브라우저에서 생성하고 앨범 입력으로 선택한다. 실제 동의 모달/POST 후 서버가 발급한 서명 URL로 PUT 요청을 한다.
3. PUT 경계만 가로채어 모의 저장소에 같은 바이트와 MD5 ETag를 등록한다. 실제 upload-complete가 서버의 HEAD 메타데이터와 파일 크기·MIME·AES256 헤더·ETag를 검증하고 로컬 DB에 UPLOADED로 확정한다.
4. 12문항을 화면에서 순서대로 답하고 진행률 1~12를 확인한다. 실제 survey-answers가 응답과 업로드 관계를 저장한다. 고정 응답은 OSNW에 해당하지만 화면에 영어 코드를 다시 노출하지 않는다.
5. 실제 analyze가 동의/소유권/객체를 재확인하고 사진 바이트를 가져와 외부 AI 형식의 JSON 응답을 처리한다. API의 `AI_ASSISTED`, OSNW, 차트·한글 리포트·화장품 카드 8개 및 면책 문구를 확인한다. 유료 AI 모델에 대한 요청은 없다.
6. 다른 브라우저의 실제 게스트 증명으로 해당 리포트를 읽으면 403인지 확인한다.
7. 실제 Google authorize에서 state·PKCE challenge·암호화 쿠키를 생성한다. 외부 공급자 화면만 모의하고 실제 콜백 POST는 앱에서 실행한다. 모의 토큰 교환도 verifier의 SHA-256이 challenge와 일치하고 코드를 한 번만 사용할 수 있는지 검사한다. 공급자 측 논리 redirect URI는 HTTPS 예약 도메인이고, 테스트가 브라우저 리디렉션만 로컬 콜백 화면으로 매핑한다. 프로덕션의 HTTPS 설정 검증을 완화하지 않는다.
8. 로컬 DB에서 이미지/진단의 회원 소유자가 같은지, 리포트가 이전과 동일한지, 별도 게스트의 기록이 그대로인지 확인한다. 게스트 쿠키 폐기와 마이페이지의 실제 이력 표시를 확인한다.
9. 잘못된 state와 쿠키 폐기 후 재시도가 400으로 거절되고 회원이 생성되지 않으며 공급자 교환 횟수가 늘지 않는지 검사한다.

## 측정과 한계

320·375·1280 CSS px에서 같은 흐름을 실행한다. CDP로 latency 40ms, 다운로드 9Mbps, 업로드 1.5Mbps인 4G 조건을 명시한다. CPU 감속은 적용하지 않는다. 각 새 컨텍스트에서 실제 `first-contentful-paint` 값을 읽으며 값이 없으면 검사 실패로 처리한다. Navigation Timing 값을 FCP처럼 대체하거나 임계치를 완화하지 않는다.

- 홈 FCP ≤1000ms.
- 실제 analyze 버튼 동작부터 API 응답까지 ≤10000ms. 공급자 응답은 빠른 로컬 모의이므로 실제 상용 모델의 지연/SLA를 검증하지 않는다.
- 홈 탐색 시작부터 차트와 추천 카드가 준비될 때까지 TTV ≤180000ms. 자동 응답 속도이며 사람의 실제 12문항 답변 시간에 대한 실사용 지표가 아니다. 사진 전송도 외부 S3가 아니라 모의 경계이므로 실제 원격 업로드 품질을 대표하지 않는다.
- 화장품 카테고리/검색, 시술 고민 필터의 상태 변경부터 DOM 반영 후 프레임까지 ≤300ms. 현재 필터는 이미 받은 자료를 브라우저에서 거르므로 원격 검색 API SLA로 부르지 않는다.
- 가로 넘침, 실제 면책 문구와 보관함 노출을 확인한다. 시술의 전국 대표 시세나 의료 검수를 완료했다는 의미는 아니다.

## 격리와 정리

preload는 지정된 예약 S3 도메인·가짜 AI/AWS 자격 증명·loopback의 sikin_dev/sikin_test:55432 외에는 시작을 거절한다. Node 외부 통신을 금지하고 등록한 S3·AI·Google 응답만 모의한다. 브라우저도 앱·모의 S3·모의 Google 외 요청을 차단한다. 실제 AWS 객체·상용 AI 크레딧·Google/Kakao 운영 계정이나 로그인은 사용하지 않는다. TLS 검증을 끄거나 테스트 CA를 시스템에 설치하지 않는다.

기존 동의 fixture를 재사용하여 로컬 전용 약관과 가상 상품을 생성한다. 원래 활성 약관 ID를 보관하고 종료 시 복구한다. 본 테스트 소유의 게스트·회원·진단·이미지·동의·AI 감사·OAuth 시도·상품만 정리하며 DB를 reset/drop하지 않는다. 중단 시 `/tmp/sikin-core-<UUID>.json`의 0600 상태 파일을 이용해 `node --conditions=react-server --import tsx tests/fixtures/core-journey-data.ts cleanup <상태파일>`로 같은 로컬 정리 명령을 실행할 수 있다.

새 ign8t 키는 개인 MCP 설정에만 저장하고 기존 설정을 보존했다. 새 연결에서 project → master_spec → next_task를 순서대로 읽었으며 스펙/규칙이 기존에 전문을 읽은 ready/non-stale 버전과 같음을 확인했다. 프로젝트의 실제 tests 경로·부호화 게스트·동의·한글 리포트·중립 가격 표현을 유지했다. 기존 환경 삭제·8b4c542 복구·공개 배포·운영 약관 활성화는 수행하지 않는다.
