# 분석 진행 화면과 SSE

ign8t 작업 `08f11698-cd6c-4b86-a110-72b616b9c1c4`를 구현합니다. 외부 로그인/AI 키 등록과 가격 자료 조사가 필요한 작업을 기다리는 동안, 이미 구현된 문진→리포트 흐름을 끝까지 연결하는 작업을 우선했습니다. 공개 배포나 실제 유료 AI 호출은 수행하지 않습니다.

## 사용자 흐름

문진 저장 후 **피부 리포트 보기**를 누르면 `/diagnostic/progress?sessionId=UUID`로 이동합니다. 기존 분석 POST를 시작하고, 서버가 실제 발행한 사진 참고 정보 확인→문진 정리·결합→리포트 저장 단계를 표시합니다. 진행률 35/70/95는 처리 단계이며 남은 시간이나 정확도의 비율이 아닙니다. 시간 경과만으로 단계를 꾸미거나 사진을 분석한 것처럼 표시하지 않습니다. 사진 AI를 사용할 수 없으면 첫 단계에 미적용 상태를 남기고 문진 기반 결과로 전환합니다.

완료되면 현재 저장소의 실제 결과 경로 `/diagnostic/result/[reportId]`로 이동합니다. 문진 기반 전환 안내를 잠시 표시하고 결과 화면에서도 분석 출처를 계속 확인할 수 있습니다. 면책 안내는 대기 화면과 앱 셸에 유지합니다.

직접 URL을 열거나 새로고침한 경우에는 이미 있는 작업을 관찰합니다. GET이나 단순 페이지 방문만으로 새 AI 요청을 시작하지 않습니다. 앱 안에서 리포트 버튼을 누른 클라이언트 동작만 최초 자동 POST를 허용합니다. 이 클라이언트 표시 자체는 인증 수단이 아니며, POST는 기존 서버 인증·소유권·출처·시간당 한도 검사를 그대로 통과해야 합니다.

연결이 끊기면 1초 간격으로 최대 2회 재연결합니다. 실패 상태에서는 **리포트 생성 상태 확인하기**를 눌러 동일한 문진 ID의 기존 POST를 재확인합니다. 저장된 리포트가 있으면 같은 결과를 반환하고, 없다면 동일 문진의 분석을 준비합니다. 중복 요청은 기존 오케스트레이터의 원자적 claim과 리포트 고유 제약으로 처리합니다. SSE를 지원하지 않는 브라우저나 실시간 전송 실패 시에도 POST 응답으로 저장된 결과를 확인할 수 있습니다.

## 서버 계약

`GET /api/v1/diagnostics/progress/[sessionId]`는 읽기 전용입니다. 서명된 HttpOnly 게스트 증명 또는 실제 유효한 회원 세션을 확인합니다. 원시 게스트 ID 헤더는 인증 수단으로 쓰지 않습니다. 잘못된 ID는 400, 인증 없음은 401, 타인 세션은 403, 없는 세션은 404입니다.

성공 응답은 `text/event-stream; charset=utf-8`, `Cache-Control: private, no-cache, no-store, no-transform`, `Vary: Cookie`, `X-Accel-Buffering: no`를 사용합니다. 공통 `proxy.ts`의 응답 헤더가 라우트 헤더를 덮어쓰므로 해당 스트림 경로에서 `no-transform`을 보존합니다. 다른 응답의 private/no-store 정책은 바꾸지 않습니다.

- `event: progress`: 실제 단계와 단계 번호·진행률·안내·사진 AI 미적용 여부.
- `event: complete`: 저장된 리포트 ID·타입·완료 시각.
- `event: fallback`: 저장된 문진 리포트 ID와 `TIMEOUT`, `AI_SERVICE_UNAVAILABLE`, `QUESTIONNAIRE_ONLY` 사유. 키 미설정·사진 없음은 서비스 장애로 단정하지 않습니다.
- `event: error`: 안전한 오류 코드와 재확인 안내. 내부 오류·토큰·사진 주소·문진 응답을 노출하지 않습니다.
- 연결 유지용 SSE 주석을 주기적으로 전송합니다. 종료·취소·요청 중단 시 타이머와 구독을 해제합니다.

기존 `pg`와 PostgreSQL LISTEN/NOTIFY를 사용합니다. 단계가 별도 서버 프로세스에서 발행되어도 같은 DB의 구독자에게 전달됩니다. 프로세스 내 구독자들은 하나의 LISTEN 연결을 공유하고 마지막 구독자가 떠나면 연결을 닫습니다. 새 의존성·테이블·마이그레이션을 추가하지 않습니다. LISTEN은 세션 연결을 지원하는 DB 연결이 필요합니다. 알림 전송 실패는 명시적으로 기록하고, 리포트 생성 자체는 중단시키지 않습니다.

스트림은 반초마다 DB의 실제 종결 상태를 다시 확인하여 연결 전 완료, 재접속, 알림 누락을 복구합니다. 매 이벤트와 재확인마다 소유권 및 회원 세션 유효성을 다시 검사합니다. 회원으로 이전된 게스트 기록이나 폐기된 로그인 토큰은 연결 후에도 차단합니다.

## 타임아웃과 스펙 차이

8초 제한과 문진 기반 전환은 기존 오케스트레이터/AI 게이트웨이가 소유합니다. 스트림이 별도의 8초 타이머로 가짜 리포트 ID를 만들거나 분석을 재실행하지 않습니다. 실제 폴백 리포트가 커밋된 뒤 `fallback`을 보냅니다. 원래 요청이 중단된 등 종결 상태가 없으면 관찰 스트림은 12초 뒤 안전한 재확인 오류로 끝납니다. 8초가 지났다는 이유만으로 존재하지 않는 결과를 성공으로 표시하지 않습니다.

스펙 예시의 `/diagnostic/report/[reportId]` 대신 기존 `/diagnostic/result/[reportId]`를 재사용합니다. '정밀 AI 분석' 표현 대신 실제 사용한 입력과 처리 한계를 표시합니다. 사진이 없는 문진 결과도 사용할 수 있도록 `QUESTIONNAIRE_ONLY` 사유를 추가했습니다. 브라우저 콜백·폴백 결과·제한 시간 검증에는 모의 공급자와 격리된 로컬 DB만 사용합니다.
